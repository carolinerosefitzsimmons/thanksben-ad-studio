# Pre-rendered trusted-by logos

One flat `#002923` PNG per customer, used by the landing page's trusted-by row.
Generated by `node scripts/fetch-client-logos.mjs`, which reads `data/clients.json`.

The landing page falls back to the customer's name as text when a file is
missing, so a **missing** logo is safe. A **wrong** one is not.

## Current state: 11 of 29

**Always review the contact sheet before shipping a run of this script.** It
scrapes `og:image`, `apple-touch-icon` and favicons, and those are often not the
company's mark. In the last run it produced, among other things:

- **Trustpilot badges** for Funding Circle and Octopus Energy — a review widget
  pulled from the page, not their logo
- a **fragment of the BA speedmarque** for British Airways
- unidentifiable icons for InPost, itsu, Zalando and Improbable
- a grey plate baked behind the Pleo wordmark

All of those were deleted. The results also vary run to run, because several of
these sites rate-limit or block automated requests — a domain that worked
yesterday can fail today and vice versa.

## The fix

Set **`LOGO_DEV_TOKEN`** in `.env.local` and re-run. logo.dev is tried first and
returns real, transparent wordmarks instead of scraped favicons, which resolves
almost all of the above. It is free for low volume. Without it the script is
working from whatever happens to be on the page.

Anything still missing after that is worth dropping in by hand.
